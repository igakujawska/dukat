DUKAT — NOTATKA DO NAUKI
Wersja po wdrożeniu brakujących modułów, 20.10.2026.

1. CO POTRAFIĘ POKAZAĆ
Logowanie i rejestracja JWT, własne dane każdego profilu, konta i ich archiwizacja,
historia z kategoriami, automatyczne saldo, miesięczne budżety, cele, cykle,
przelewy, wykresy i statystyczna prognoza. Całość startuje przez Docker Compose.
Kod jest monolitem z warstwami; nie potrzebuje mikroserwisów, żeby pokazywać
świadome decyzje architektoniczne.

2. JĘZYKI, TECHNOLOGIE I NARZĘDZIA — NIE MYL ICH
Java: logika backendu, encje, DTO, serwisy, kontrolery, testy.
TypeScript: kod Angulara; dodaje typy do JavaScriptu, a build tworzy JavaScript.
JavaScript: język wykonywany w przeglądarce; także skrypt indeksujący źródła.
HTML: struktura formularzy i widoków. CSS: wygląd, szkło, kolory, responsywność.
SQL: schemat, relacje i migracje. PostgreSQL to silnik bazy, nie osobny język.
Spring Boot uruchamia i konfiguruje Javę. Spring MVC obsługuje HTTP.
Spring Security weryfikuje JWT. Hibernate/JPA mapuje obiekty na tabele.
Spring Data tworzy repozytoria. Flyway wersjonuje zmiany schematu.
Angular to framework frontendu, RxJS obsługuje strumienie odpowiedzi HTTP.
Maven/pom.xml buduje Javę i dobiera zależności; npm/package.json — frontend.
Docker buduje obrazy i uruchamia procesy w kontenerach; Compose łączy trzy usługi.
Dockerfile jest przepisem obrazu, obraz jest szablonem, kontener to uruchomiony proces.
Wolumen przechowuje pliki PostgreSQL poza cyklem życia kontenera.
Postman wysyła żądania HTTP bez klikania UI. Swagger opisuje API i pozwala je wywołać.
pgAdmin to klient do oglądania/tworzenia zapytań PostgreSQL; nie zapisuje za serwis.
Terminal uruchamia polecenia. Git zapisuje historię kodu; GitHub ją hostuje.

3. KLASA, INTERFEJS, RECORD, ENUM
Klasa ma stan, konstruktor i metody działające w runtime, np. AccountService.
Encja JPA jest klasą z tożsamością i pustym konstruktorem dla ORM, np. Account.
Interfejs repozytorium opisuje kontrakt; Spring Data tworzy implementację/proxy.
Nie trzeba tworzyć AccountRepositoryImpl, bo JpaRepository zapewnia CRUD.
Interfejs TypeScript Account/Goal opisuje JSON wyłącznie na etapie sprawdzania typów.
Nie jest tabelą, nie wykonuje żądania i nie waliduje automatycznie danych runtime.
Record Java jest dobry dla niemutowalnego kontraktu DTO: generuje konstruktor,
accessory name() itd., equals/hashCode/toString. Nie używamy go tu jako encji JPA.
CreateTransactionRequest jest zwykłą klasą DTO z getterami/setterami — to też poprawne;
dla niej używamy getAmount(), a dla recordu request.amount().
Enum definiuje skończony zbiór wartości: TransactionType i Role.
Role nie potrzebuje własnej tabeli/repozytorium, bo nie jest edytowalnym słownikiem.
Category jest encją, bo użytkownik może tworzyć i zmieniać swoje kategorie.
OwnedResource jest wspólną klasą mapowania id/owner; nie jest osobnym zasobem API.

4. DLACZEGO KONTO MA MODEL, REPOZYTORIUM, SERWIS I KONTROLER
Model opisuje stan oraz relacje. Repozytorium pobiera/zapisuje rekordy.
Serwis realizuje reguły, np. zamknięcie tylko przy saldzie 0 i kontrolę właściciela.
Kontroler zamienia HTTP/JSON na wywołanie serwisu, stosuje Valid i statusy.
DTO określa, co klient może przesłać/zobaczyć. Encja zawiera więcej szczegółów bazy.
Rozdzielenie pozwala testować reguły bez HTML i zmieniać widok bez zmiany bazy.
Nie każda klasa potrzebuje repozytorium: DTO, enum, konfiguracja, FinancialLedger,
ForecastService i komponent ikony nie reprezentują oddzielnej tabeli.

5. MAPA DOMENY I ODPOWIEDZIALNOŚCI
User: login, hash BCrypt, e-mail, rola, aktywność. Odpowiedzi UserResponse nie mają hasła.
Account: rodzaj, saldo, archiwizacja i wersja; ma jednego ownera.
Transaction: historyczny wpis wskazujący konto i kategorię; dodatkowo przelew/cykl,
jeśli to z nich powstał. Kwota dodatnia, kierunek wynika z typu.
Category: edytowalny słownik danego właściciela; wyłączenie nie kasuje historii.
Budget: jedna kategoria + miesiąc + limit; wydatki pochodzą z historii, nie z formularza.
Goal: nazwa, kwota docelowa, postęp, termin. Ręczna wpłata do postępu nie obciąża konta.
RecurringPayment: szablon przyszłych zapisów; ma konto, kategorię, typ, kwotę, termin,
częstotliwość, aktywność i ostatni błąd. To nie jest pojedyncza zaksięgowana transakcja.
Transfer: koreluje źródło i cel z dwiema pozycjami Transaction (TRANSFER_OUT/IN).
Household/Membership i SettlementService są szkicem dodatkowego zakresu — brak
pełnego wspólnego budżetu/rozliczeń gospodarstwa w UI. Nie przedstawiaj tego jako gotowej funkcji.

6. PRZEŚLEDŹ JEDEN WYDATEK
HTML/ngModel -> AppComponent.saveTransaction -> TransactionService Angulara ->
POST /api/transactions z Authorization: Bearer -> proxy/Nginx -> filtr Spring Security ->
TransactionController -> CreateTransactionRequest/Valid -> TransactionService Java ->
FinancialLedger -> blokada konta właściciela -> aktywna własna kategoria ->
zmiana salda i zapis historii przez JPA -> COMMIT PostgreSQL -> DTO odpowiedzi ->
ponowny GET kont, historii, kategorii i prognozy -> signal/computed -> nowy widok.
JSON wejścia ma date i categoryId; odpowiedź ma transactionDate, category i categoryId.
Ujemna kwota lub >2 miejsca po przecinku daje 400 i nie zmienia salda.
Ręczne wydatki mogą doprowadzić saldo do wartości ujemnej; przelew wymaga środków.
Nie zmieniaj salda drugi raz w Angularze — serwer jest źródłem prawdy.

7. LOGOWANIE, JWT I WŁAŚCICIEL
Rejestracja zapisuje hash BCrypt i własne domyślne kategorie. Login porównuje hash.
JWT ma podpis, issuer, subject, datę wydania i wygaśnięcia (godzina), uid i role.
Podpis potwierdza integralność; JWT nie szyfruje payloadu. Base64 to kodowanie.
Angular trzyma token w pamięci; nie zapisuje hasła ani tokenu w localStorage.
Odświeżenie karty wymaga logowania. Logout czyści stan i anuluje trwające odczyty.
Serwer nie utrzymuje sesji HTTP. Publiczne są auth, dokumentacja i health.
CurrentUser ustala profil z JWT, a repozytoria filtrują po ownerId.
Samo JWT nie zapewnia izolacji. Nie przyjmujemy ownerId od klienta.
Próba użycia cudzego id daje 404. Nie zwracamy User jako surowej encji.
CSRF jest wyłączone dla API z nagłówkiem Bearer, bez cookies uwierzytelniania.
CORS nie jest potrzebny w przepływie same-origin przez proxy. Nie dodajemy *.
Na localhost działa HTTP; publiczne wdrożenie wymaga HTTPS.
Lokalny bootstrap używa .env tylko przy pierwszym tworzeniu użytkownika.

8. SPÓJNOŚĆ I WSPÓŁBIEŻNOŚĆ
Transactional daje atomowość i rollback, lecz samo nie zapobiega utraconej aktualizacji.
AccountRepository stosuje PESSIMISTIC_WRITE. Drugi zapis tego konta czeka.
Account ma też Version. Przelew blokuje dwa konta w stałej kolejności id,
zmienia dwa salda, zapisuje transfer i dwie pozycje historii w jednej transakcji.
TRANSFER_IN/OUT nie są dochodem/wydatkiem; nie trafiają do sum budżetu/modelu.
Konto archiwizujemy przy saldzie 0, kategorię wyłączamy; nie kasujemy powiązanej historii.
Zmiana nazwy kategorii jest widoczna przez FK. Stare tekstowe pole jest snapshotem.
Cykle: blokada szablonu + unikalny indeks (recurring_payment_id,scheduled_date).
Procesor sprawdza termin przed zapisem, dlatego ponowne wykonanie nie dubluje obciążenia.
Maks. 12 terminów w jednej partii. Kolejne przejście uzupełnia dalsze zaległości.
Dzień miesiąca ma kotwicę: 31.01 -> koniec lutego -> 31.03. Tydzień to +7 dni.
Brak konta/wyłączona kategoria powoduje rollback i błąd do poprawienia, nie częściowy zapis.
Ręczne POST nie mają jeszcze klucza idempotencji: ponowiony prawidłowy POST może
utworzyć kolejną legalną transakcję. To osobny temat od blokad i idempotencji cyklu.

9. MIGRACJE I TRWAŁOŚĆ
V1 obejmuje istniejący schemat albo tworzy go od zera. Baseline=0 to punkt startowy
historii istniejącej bazy, nie skasowanie danych.
V2 dodaje właścicieli, kategorię FK, przelewy, indeksy i pola harmonogramu.
V3 zapewnia unikalny login/e-mail bez rozróżniania wielkości liter.
V4 zachowuje dzień miesiąca w harmonogramie.
Hibernate validate tylko porównuje mapowanie z tabelami. Flyway zmienia schemat.
Nie edytujemy zastosowanej migracji; dopisujemy następną, bo Flyway sprawdza checksum.
Przed zmianą wykonano pg_dump i odtworzenie w osobnej bazie dukat_upgrade_check.
Porównano skróty starych pól kont/transakcji — migracja zachowała ich wartości.
Wolumen zapewnia trwałość po restarcie kontenera, lecz nie chroni przed usunięciem,
błędem aplikacji czy awarią dysku. Backup wymaga również sprawdzenia odtworzenia.

10. SIEĆ I PORTY
Windows/przeglądarka: localhost:4200 UI, localhost:8082 API, localhost:5433 PostgreSQL.
W kontenerze backendu localhost wskazuje ten kontener. Baza jest pod db:5432.
5433:5432 to host:kontener, nie dwie wersje PostgreSQL.
Port 8082 already in use = drugi proces próbuje użyć zajętego portu.
Używaj jednego trybu: pełny Docker ALBO baza Docker + Java IntelliJ + ng serve.
Start-Dukat.ps1 pokazuje proces/PID, ale nie zabija dowolnego procesu.
HTTP 200 z HTML w żądaniu API często oznacza brak proxy i fallback index.html.
401 = brak/poprawność/ważność uwierzytelnienia, 403 = zakaz, 404 = brak własnego zasobu,
400 = złe dane, 409 = konflikt danych, 502 = proxy nie może połączyć się z backendem.

11. ANGULAR — CO WARTO UMIEĆ WYJAŚNIĆ
Component łączy klasę/HTML/CSS; standalone ma zależności w imports.
FormsModule i ngModel łączą pola ze stanem formularza. Min/required poprawiają UX,
ale backend musi powtórzyć walidację, bo każdy może wywołać API bez formularza.
signal przechowuje stan, computed wylicza wartości zależne, np. miesięczne wydatki.
Serwis HTTP korzysta z inject(HttpClient); komponent nie tworzy własnego klienta.
Observable opisuje przyszłą odpowiedź; subscribe ją obsługuje, finalize kończy stan loading.
forkJoin czeka na komplet odczytów. Wylogowanie anuluje oczekujące żądania,
żeby stara odpowiedź nie przywróciła danych po logout.
Input przekazuje dane do PlanningComponent, Output.changed prosi rodzica o refresh.
Nowe moduły mają osobne DTO/interfejsy w services/planning.ts i wspólny komponent widoków.
@ przypomina adnotacje Javy, ale TypeScript używa dekoratorów.
@if/@for/@switch/@case/@empty/@else w HTML są składnią szablonu Angulara,
a @media/@import w CSS regułami CSS — nie są adnotacjami Javy ani dekoratorami TS.

12. MODELE I ANALITYKA
Dashboard nie pokazuje wymyślonych sum: pobiera historię zalogowanego użytkownika.
Prognoza bierze maks. 12 miesięcy przed miesiącem celu, bez bieżących częściowych danych.
Mniej niż 3 kolejne miesiące -> null / INSUFFICIENT_DATA, a nie 0 zł.
3–5 miesięcy -> średnia ostatnich trzech. Od 6 miesięcy porównujemy średnią,
trend OLS z maks. 6 punktów i naiwny ostatni miesiąc przez walidację kroczącą/MAE.
Miesiąc bez operacji przerywa ciąg; tylko przychody oznaczają 0 zapisanych wydatków.
Miesiąc z samymi przelewami nie jest historią wydatków do modelu.
MAE użyte do wyboru modelu nie jest niezależnym testem końcowym. Nie mamy jeszcze
holdoutu, sezonowości, przedziałów ani niezależnego dowodu kompletności danych.
Szczegóły: MODEL_CARD_DUKAT.md. Prosta regresja jest modelem uczonym z danych;
nie trzeba udawać osobnego serwera ML ani dopisywać fikcyjnej trafności.

13. JAK POKAZAĆ PROJEKT W 7 MINUT
1) Start jednym skryptem, trzy zdrowe kontenery i porty.
2) Login/rejestracja; drugi profil nie widzi pierwszego.
3) Dodaj dwa konta, przychód i wydatek; pokaż zmienione saldo i walidację.
4) Przelew: dwa wpisy historii i niezmieniona suma pieniędzy/przychodów/wydatków.
5) Limit budżetu i postęp celu; wyjaśnij różnicę między postępem a przepływem pieniędzy.
6) Cykl: aktywacja, termin, ręczne wykonanie należnych, ponowienie bez duplikatu.
7) Swagger/Postman, migracje, testy i ograniczenia prognozy.
Pytaj siebie: gdzie sprawdzamy regułę, kto jest właścicielem, co po awarii,
co po retry i co gdy dwa żądania przyjdą jednocześnie?

14. WSZYSTKIE ADNOTACJE JAVA I DEKORATORY TYPESCRIPT
Indeks wszystkich lokalizacji i plików: INDEKS_PLIKOW_I_ADNOTACJI_DUKAT.txt.
Poniższe definicje obejmują kod produkcyjny i testy.

@Autowired
Spring wstrzykuje zależność. U nas pole testu pobiera JdbcTemplate/JwtEncoder; w kodzie produkcyjnym zwykle używamy konstruktorów bez tej adnotacji.

@Bean
Metoda konfiguracji zwraca obiekt zarządzany przez Spring, np. filtr SecurityFilterChain, PasswordEncoder, JwtEncoder.

@BeforeEach
JUnit uruchamia metodę przed każdym testem, aby przygotować niezależne dane i mocki.

@Column
Mapowanie pola na kolumnę, np. nullable=false. Nie jest walidacją JSON; schemat produkcyjny tworzą SQL Flyway.

@Component
Java: ogólny bean Springa (inicjalizator, scheduler). Angular/TypeScript: dekorator łączący klasę, HTML, CSS i imports komponentu. To dwa różne mechanizmy o podobnej nazwie.

@ConditionalOnProperty
Tworzy bean tylko przy określonej konfiguracji. Scheduler wymaga app.scheduling.enabled=true; w testach automatyczne księgowanie jest wyłączone.

@Configuration
Klasa definiująca konfigurację Springa i metody Bean, np. JwtConfig/SecurityConfig/OpenApiConfig.

@Container
Pole Testcontainers zarządzane przez rozszerzenie JUnit. PostgreSQL testów ma losowy port i własne dane.

@DeleteMapping
Obsługa HTTP DELETE. U nas konto/kategoria są archiwizowane, cykl wstrzymywany, a budżet/cel usuwany.

@Digits
Maksymalna liczba cyfr całkowitych i po przecinku w DTO. Nie zaokrągla po cichu kwoty 1.001 do groszy, lecz odrzuca ją.

@DynamicPropertySource
Test podaje Springowi dynamiczny URL, login i hasło tymczasowego PostgreSQL.

@Email
Sprawdza format e-maila w rejestracji; nie dowodzi istnienia skrzynki ani potwierdzenia adresu.

@EnableScheduling
Włącza wykonywanie metod Scheduled. Jest przy klasie startowej aplikacji.

@Entity
Klasa mapowana na rekordy bazy przez JPA/Hibernate. Account jest encją, DTO nią nie jest.

@EntityGraph
Określa relacje dociągane przy odczycie, np. konto i kategoria historii. Pomaga ograniczyć N+1 i odczyty poza transakcją.

@Enumerated
Enum zapisujemy jako STRING, np. EXPENSE. Zmiana nazwy stałej wymaga świadomej migracji istniejących danych.

@ExceptionHandler
Wskazuje wyjątki obsługiwane przez metodę. GlobalExceptionHandler mapuje je na 400/401/403/404/409/500.

@GeneratedValue
Id generuje baza przez strategię IDENTITY. Klient tworzący konto nie nadaje własnego id.

@GetMapping
Odczyt HTTP GET, np. lista kont albo prognoza. Odczyt nie powinien zmieniać pieniędzy.

@HostListener
Angular podpina zdarzenie, np. Escape zamyka dialog. Nie ma związku z serwerem HTTP.

@Id
Klucz główny encji. W encjach OwnedResource identyfikator jest odziedziczony.

@Injectable
Dekorator serwisu Angulara. providedIn:root udostępnia instancję przez DI, np. SessionService.

@Input
Angular: dane od rodzica do komponentu, np. konta, kategorie i miesiąc dla PlanningComponent.

@JoinColumn
Nazwa kolumny relacji, np. account_id/category_id/owner_id. Faktyczny FK jest też w migracji SQL.

@JsonIgnore
Nie serializuje właściciela do JSON. Główna ochrona odpowiedzi to i tak jawne DTO, bez hasła.

@Lock
Tryb blokowania zapytania JPA. PESSIMISTIC_WRITE blokuje modyfikowane konta/szablony aż do końca transakcji.

@ManyToOne
Wiele rekordów wskazuje jeden rekord, np. wiele transakcji jedno konto, wiele kont jednego właściciela.

@MappedSuperclass
Wspólne mapowane pola id/owner w OwnedResource, dziedziczone do tabel encji. Nie powstaje tabela owned_resource.

@NotBlank
Tekst nie może być null, pusty ani składać się ze spacji, np. opis operacji.

@NotNull
Wartość musi istnieć. Sama adnotacja nie odrzuca pustego tekstu ani ujemnej liczby.

@Operation
Opis operacji w OpenAPI/Swagger. Dokumentuje zachowanie; nie wykonuje autoryzacji ani walidacji.

@Output
Angular: zdarzenie od dziecka do rodzica. changed powoduje odświeżenie sald, expired wraca do logowania.

@Override
Kompilator sprawdza, że implementujemy/nadpisujemy istniejącą metodę, np. CommandLineRunner.run.

@Param
Wiąże argument repozytorium z nazwanym parametrem zapytania JPQL, np. :ownerId.

@PathVariable
Pobiera fragment ścieżki, np. id z /api/accounts/5. To id nadal wymaga kontroli właściciela.

@Pattern
Dopuszczalny wzorzec tekstu, np. INCOME|EXPENSE albo miesiąc YYYY-MM. Nie jest zabezpieczeniem wszystkich reguł biznesowych.

@Positive
Liczba większa od zera. Kwota transakcji/przelewu musi być dodatnia.

@PositiveOrZero
Dopuszcza zero, np. saldo początkowe albo początkowy postęp celu.

@PostMapping
HTTP POST tworzący zasób albo wykonujący akcję: logowanie, zapis transakcji, przelew, wykonanie cyklu.

@PutMapping
HTTP PUT edytujący dozwolone pola istniejącego zasobu, np. nazwę konta lub limit budżetu.

@Query
Jawne JPQL repozytorium. Posługuje się nazwami encji i pól Javy, np. a.owner.id, a nie nazwami kolumn SQL.

@Repository
Bean warstwy danych. Interfejs JpaRepository dostaje implementację Spring Data; nie piszemy klasy implementującej CRUD ręcznie.

@RequestBody
Zamienia JSON żądania na DTO. Nie czyni treści zaufaną — dalej są Valid i reguły serwisu.

@RequestMapping
Wspólny prefiks kontrolera, np. /api/accounts.

@RequestParam
Parametr query string, np. ?month=2026-10 albo ?includeArchived=true.

@ResponseStatus
Status odpowiedzi metody, np. 201 po utworzeniu i 204 po archiwizacji bez body.

@RestController
Kontroler HTTP zwracający dane, zwykle JSON. Nie renderuje widoku Thymeleaf.

@RestControllerAdvice
Globalna obsługa odpowiedzi/wyjątków kontrolerów. U nas jeden wspólny GlobalExceptionHandler.

@Scheduled
Harmonogram w procesie backendu. Co minutę wyszukuje należne cykle. Backend musi działać, aby wykonywać zadania.

@Schema
Opisy pól/modeli DTO w Swaggerze, np. jednostki, format i null w prognozie. Nie zastępuje NotNull/Positive.

@SecurityRequirements
Pusta lista wymagań dokumentacji dla publicznego AuthController; reguły runtime nadal ustawia SecurityConfig.

@Service
Bean warstwy reguł biznesowych. Nie tworzymy go samodzielnie przez new w kontrolerze.

@Size
Długość tekstu/listy, np. nazwa do 100 znaków lub hasło 10–72 znaki. Limit bajtów UTF-8 hasła dodatkowo sprawdza serwis.

@SpringBootApplication
Punkt startowy Boot: konfiguracja, autokonfiguracja i skanowanie komponentów w pakiecie/podpakietach.

@SpringBootTest
Test uruchamia kontekst aplikacji; RANDOM_PORT sprawdza prawdziwe HTTP na wolnym porcie.

@Table
Nazwa tabeli encji, np. transactions. Schemat zmieniamy przez Flyway, a nie ręczne kliknięcia pgAdmina.

@Test
JUnit oznacza metodę jako test. Test ma wykrywać błąd zachowania, np. utraconą aktualizację salda.

@Testcontainers
Rozszerzenie JUnit uruchamia i sprząta oznaczone kontenery testowe. Nie usuwa wolumenu aplikacji.

@Transactional
Wspólna transakcja bazodanowa. Saldo+historia albo dwie strony przelewu zapisują się razem lub cofają przy RuntimeException. readOnly oznacza odczyt. Wywołanie musi przejść przez proxy Springa, dlatego processor jest osobnym beanem. Sama adnotacja nie chroni przed wszystkimi wyścigami.

@Valid
Uruchamia walidację ograniczeń DTO w kontrolerze. Błędna kwota daje 400 przed logiką finansową.

@Value
Wstrzykuje wartość konfiguracji Springa, np. TTL lub klucz z zmiennej środowiskowej. To nie Angular binding.

@Version
Wersja rekordu Account dla kontroli równoczesnych aktualizacji. JPA porównuje ją przy UPDATE; nie zastępuje polityki retry ani FK.

15. GIT — BEZ JEDNEGO WIELKIEGO COMMITA
Najpierw git status i diff, potem zaznacz konkretną grupę z PLAN_COMMITOW.md.
add wybiera zmiany, commit zapisuje lokalną historię, push wysyła do zdalnego repo.
Sprawdź git diff --cached przed commitem. Nie zaznaczaj .env, target, node_modules,
dist ani logów. Sam .gitignore nie usuwa sekretu z wcześniejszej historii.
Autorka powinna umieć przejść od formularza do SQL i wyjaśnić własne decyzje.
