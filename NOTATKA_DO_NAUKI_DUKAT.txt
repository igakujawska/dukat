DUKAT — NOTATKA DO NAUKI I PRZYGOTOWANIA DEMONSTRACJI
Stan: 20 października 2026 r. / Java 21, Spring Boot 4.1, Angular 22

1. CO ZBUDOWAŁAM I JAK TO UCZCIWIE PRZEDSTAWIĆ
============================================
Dukat ewidencjonuje finanse osobiste. Potrafi pobrać i dodać konta, zapisać
przychód lub wydatek, przeliczyć saldo, pokazać historię, filtry, wykresy
oraz miesięczną prognozę wydatków. Frontend ma szafirowy motyw, półprzezroczyste
panele i układ na telefon. Liczby finansowe pochodzą z API, a nie z dekoracji.

To demonstracyjny monolit warstwowy z osobnym frontendem SPA.
Enterprise oznacza tu przemyślany podział odpowiedzialności i świadome decyzje,
a nie samą liczbę klas. Nie ma jeszcze kompletnej produkcyjnej autoryzacji,
izolacji danych użytkowników, audytu, migracji i ochrony współbieżnych sald.
Nie należy przedstawiać projektu jako gotowego systemu bankowego.

Przykładowy opis w portfolio:
„Aplikacja Angular + Spring Boot + PostgreSQL. REST API z walidacją,
transakcyjną aktualizacją sald i testami. Prognozowanie wydatków porównuje
średnią ruchomą, regresję liniową i model naiwny w walidacji czasowej.
Projekt rozwijałam z pomocą AI; potrafię wyjaśnić przepływ, testy i ograniczenia.”

JSON: format danych HTTP i konfiguracji; nie jest językiem programowania.
XML: format pom.xml. YAML: format docker-compose.yml.
PowerShell/terminal: uruchamianie programów, Git, diagnostyka i budowanie.

Spring Boot uruchamia i automatycznie konfiguruje backend.
Spring MVC obsługuje kontrolery HTTP i serializację JSON.
Spring Security chroni API i sprawdza Basic Auth.
Spring Data JPA tworzy implementacje repozytoriów.
JPA jest specyfikacją mapowania obiektów; Hibernate jest jej implementacją.

Angular organizuje komponenty, formularze, DI i klienta HTTP.
RxJS dostarcza Observable, forkJoin, finalize i anulowanie subskrypcji.

Wolumen zachowuje bazę po ponownym uruchomieniu kontenera.

npm instaluje biblioteki i uruchamia skrypty frontendu; Angular CLI buduje SPA.
Postman pozwala wysłać HTTP bez interfejsu, np. POST /api/transactions.
pgAdmin pozwala obejrzeć tabele i wykonać SQL. Nie zastępuje backendu.
Swagger UI opisuje i pozwala wywoływać API; nie jest interfejsem aplikacji.
Git zapisuje lokalną historię. GitHub przechowuje zdalne repozytorium.
W tym projekcie nie ma jeszcze modelu Python/R ani wywołania LLM.

3. CAŁY PRZEPŁYW — OD KLIKNIĘCIA DO POSTGRESQL
=============================================
Przeglądarka -> Angular -> HttpClient -> /api przez proxy -> Spring Security
-> kontroler -> serwis -> repozytorium -> Hibernate/JDBC -> PostgreSQL.
Odpowiedź wraca jako JSON -> interfejs TypeScript -> signal -> HTML.
Proxy służy lokalnemu serwerowi developerskiemu. Po wdrożeniu potrzebna jest
osobna konfiguracja routingu, np. reverse proxy. Sam frontend nie uruchamia Javy.

Przykład wydatku 20 zł:
1. Formularz w app.html wiąże pola z transactionDraft przez ngModel.
2. saveTransaction() w app.ts wywołuje serwis Angulara.
3. services/transaction.ts wysyła POST /api/transactions z JSON i nagłówkiem Auth.
4. TransactionController odbiera DTO; @Valid uruchamia walidację.
5. TransactionService pobiera Account i odejmuje BigDecimal 20 od salda.
6. Zapisuje Account i Transaction w jednej transakcji bazodanowej.
7. Kontroler zwraca TransactionResponse i status 201.
8. Frontend odczytuje aktualne konta i historię. Nie zgaduje salda samodzielnie.

Uwaga na nazwy kontraktu: przy tworzeniu operacji żądanie ma pole date,
a odpowiedź pole transactionDate. Nazwy JSON muszą zgadzać się po obu stronach.
Saldo początkowe konta nie jest automatycznie przychodem w historii.

4. DLACZEGO KLASA, INTERFEJS, ENUM LUB RECORD
===========================================
Klasa posiada stan i zachowanie. Account jest klasą, bo JPA odtwarza i śledzi
obiekt encji. Serwis i kontroler są klasami, bo wykonują działania i mają DI.
Klasa komponentu Angulara przechowuje stan widoku oraz obsługuje zdarzenia.

Interfejs Java opisuje kontrakt. AccountRepository extends JpaRepository<Account,
Long> oznacza „obsługuj encję Account z identyfikatorem Long”. Spring Data
buduje implementację/proxy w czasie działania. Sama nazwa interfejsu nie
łączy z bazą — robi to skonfigurowana infrastruktura Spring Data i JPA.
Nie trzeba tworzyć ręcznie klasy AccountRepositoryImpl dla zwykłego CRUD.

Interfejs TypeScript Account opisuje kształt JSON: id, name, accountType,
balance. Nie jest serwisem ani beanem; znika z wynikowego JavaScriptu.
Typy TypeScript nie walidują automatycznie JSON-a otrzymanego z sieci.

Enum zamyka zbiór dozwolonych wartości. TransactionType: INCOME/EXPENSE.
Role i HouseholdRole opisują planowane role. Ich istnienie nie wdraża
samodzielnie kontroli dostępu. @Enumerated(STRING) zapisuje nazwę stałej.

Record Java jest zwięzłym nośnikiem danych: konstruktor, akcesory, equals,
hashCode i toString. Pola są final, ale record nie gwarantuje głębokiej
niezmienności zawartych kolekcji. DTO konta/przelewu/odpowiedzi to recordy.
Record request.amount() różni się od klasy request.getAmount().
CreateTransactionRequest jest zwykłą klasą z getterami; dlatego serwis używa
getAmount(), getAccountId(), getDate(), getType(), a nie składni recorda.

5. PO CO TYLE WARSTW
====================
Model/encja: dane i mapowanie tabel, klucze oraz relacje.
DTO: kontrakt wejścia/wyjścia API. Klient nie musi wysyłać całej encji ani id.
Repository: dostęp do danych, bez reguł dotyczących tego, ile odjąć od salda.
Service: przypadki użycia i reguły; granice transakcji, prognozowanie.
Controller: ścieżki HTTP, odebranie żądania, delegacja i odpowiedź.
ExceptionHandler: spójne statusy i komunikaty błędów.
Config: sposób składania i uruchomienia infrastruktury.

Nie każda encja potrzebuje wszystkich warstw. Warstwę dodajemy dla
odpowiedzialności i przypadku użycia, nie dla samej symetrii folderów.
UserController obecnie korzysta z repozytorium bezpośrednio; to prostszy,
ale niedokończony fragment wymagający DTO i poprawnej obsługi haseł.
Membership ma encję, ale brak kompletnego przypadku użycia członkostwa.

7. STAN FRONTENDU — CO MUSZĘ UMIEĆ WYJAŚNIĆ
=========================================
signal przechowuje reaktywną wartość, np. accounts(). Zmiana przez set()
odświeża zależny widok. computed wylicza np. sumę sald; nie trzyma drugiej kopii.
inject pobiera zależność z kontenera DI Angulara.
Observable opisuje strumień; żądanie HttpClient wykonuje się po subskrypcji.
forkJoin czeka na zakończenie odczytu kont i transakcji; błąd jednego przerywa całość.
finalize kończy wskaźnik ładowania także po błędzie/anulowaniu.
Poprzedni odczyt prognozy jest anulowany po zmianie miesiąca, aby spóźniona
odpowiedź nie zastąpiła wyniku dla nowego filtra.
CurrencyPipe i DatePipe formatują widok. Nie zmieniają kwoty ani daty w bazie.
[(ngModel)] to wiązanie dwukierunkowe. (click) podpina zdarzenie, [disabled]
ustawia właściwość, {{ ... }} wyświetla wynik. To nie są adnotacje Javy.

8. LOGOWANIE I NAPRAWIONE BŁĘDY — DLACZEGO SAMO HASŁO NIE WYSTARCZAŁO
==================================================================
Otwieram aplikację na http://localhost:4200, backend działa na 8082.
Login domyślnego Spring Security: user. Hasło bierze się z najnowszego
uruchomienia backendu. Restart/devtools może wygenerować nowe hasło.
Login i hasło PostgreSQL z Compose nie są danymi logowania do interfejsu.
Użytkownik z tabeli users nie jest jeszcze użytkownikiem Spring Security.

Błąd HTTP 200: Angular dostał HTML strony zamiast JSON-a z /api. Serwer
frontendu działał bez wczytanego proxy. Po restarcie z właściwą konfiguracją
żądanie trafiło do Javy. HttpClient zgłasza błąd parsowania mimo statusu 200.
Dlatego kod ma teraz osobny komunikat o HTML/proxy.

Drugie okno logowania przeglądarki: odpowiedź WWW-Authenticate: Basic
uruchamiała natywny monit. API zwraca teraz 401 w JSON bez tego nagłówka,
a frontend oznacza żądanie X-Requested-With: XMLHttpRequest. Błędne hasło
ma pokazać błąd w formularzu Dukata. Chronione endpointy nadal wymagają logowania.

Authorization: Basic ... zawiera Base64 z login:hasło. Base64 nie jest
szyfrowaniem! Poza pracą lokalną potrzebne jest HTTPS i projekt właściwej sesji.
Dane są w pamięci frontendu, nie w localStorage; przeładowanie strony kończy
jego sesję. Wylogowanie czyści stan frontendu. Pełny cykl sesji serwera to
oddzielna część do dopracowania przed produkcją.

9. PROGNOZA — KONKRETNY WKŁAD Z OBSZARU ML
=========================================
GET /api/forecasts?month=2026-10 prognozuje cały październik z miesięcy
poprzedzających październik. Kwot października nie używa do dopasowania.
To prognoza miesięczna, nie przewidywanie konkretnego rachunku lub kursu akcji.

Repozytorium odczytuje maksymalnie 12 miesięcy przed miesiącem celu.
Serwis sumuje wydatki po miesiącach i bierze ciąg miesięcy od ostatniego
zamkniętego wstecz. Miesiąc bez żadnej operacji przerywa ciąg. Miesiąc
z przychodem i bez wydatku ma zero ZAPISANYCH wydatków. Kompletności ręcznie
wpisanej historii nie potrafimy potwierdzić — jest jawnym założeniem.

Przy mniej niż 3 miesiącach wynik jest INSUFFICIENT_DATA, a prognoza null.
Przy 3–5 miesiącach używamy średniej ostatnich 3 miesięcy.
Przy >=6 miesiącach porównujemy:
- MOVING_AVERAGE_3: średnia ostatnich trzech sum wydatków.
- LINEAR_TREND: regresja liniowa OLS z maks. sześciu ostatnich punktów.
  Parametry a i b są dopasowywane do danych: y = a*x + b. To uczenie modelu
  regresji, choć nie wymaga biblioteki ML. Ujemny wynik obcinamy do zera.
- LAST_MONTH: naiwny punkt odniesienia, czyli ostatnia obserwacja.

Walidacja krocząca: uczymy na wcześniejszym fragmencie, przewidujemy kolejny
miesiąc, przesuwamy granicę i powtarzamy. Modele widzą te same miesiące testowe.
MAE = średnia z |rzeczywiste wydatki - prognoza|, jednostka PLN. Mniej = lepiej.
Przy remisie preferencja wynika z kolejności modeli: średnia, trend, ostatni.
Najniższe MAE służy wyborowi modelu. Ponieważ ten sam wynik wybiera model,
NIE JEST niezależnym oszacowaniem jakości wybranego modelu na przyszłość.

Przykład: 100, 200, 300, 400, 500, 600 -> trend prognozuje 700.
Na tak sztucznie liniowym zbiorze może mieć MAE=0. To test działania,
nie dowód, że model jest idealny na prawdziwych wydatkach.
Nie ma jeszcze sezonowości, cech rachunków, niepewności, osobnego holdoutu
ani monitoringu dryfu. Dokumentacja modelu: MODEL_CARD_DUKAT.md.

Kwoty biznesowe w Javie pozostają BigDecimal. Do obliczeń modelu
statystycznego używane są double; wynik zaokrąglamy do 2 miejsc. W TypeScript
number ma arytmetykę zmiennoprzecinkową, dlatego reguł salda pilnuje backend.

10. WSZYSTKIE ADNOTACJE I DEKORATORY — ZNACZENIE W TYM KODZIE
============================================================
Spring i konfiguracja:
@SpringBootApplication — start i konfiguracja aplikacji, skanowanie komponentów
w pakiecie com.example.demoapp oraz podpakietach.
@Configuration — klasa konfiguracji beana; nie oznacza automatycznej realizacji
tego, co opisano wyłącznie komentarzem (np. JwtConfig).
@Bean — Spring rejestruje obiekt zwrócony z metody, np. SecurityFilterChain
lub konfigurację OpenAPI; zależności można następnie wstrzykiwać.
@Component — ogólny bean; DemoDataLoader i przygotowane miejsce na audyt.
@Service — komponent warstwy przypadków użycia, np. TransactionService.
@Repository — komponent dostępu do danych; implementację interfejsów JPA
zapewnia Spring Data. Interfejsy Spring Data są wykrywane także bez tej etykiety.
@EnableScheduling — uruchamia obsługę harmonogramów; bez @Scheduled na metodzie
nie powstaje konkretne zadanie cykliczne.

HTTP i błędy:
@RestController — komponent kontrolera; wyniki metod są serializowane do body,
zazwyczaj JSON. Nie zwraca nazwy szablonu Thymeleaf.
@RequestMapping — wspólny prefiks adresu kontrolera, np. /api/transactions.
@GetMapping — metoda odpowiada na GET: odczyt danych.
@PostMapping — metoda odpowiada na POST: tworzenie lub wykonanie operacji.
@RequestBody — mapuje body JSON na obiekt Java. Samo w sobie nie waliduje pól.
@RequestParam — pobiera parametr URL; tutaj opcjonalny month w prognozie.
@CrossOrigin — deklaruje politykę CORS dla kontrolera. Nie jest logowaniem
ani uprawnieniem użytkownika. Obecne origins="*" wymaga przemyślenia przy wdrożeniu.
@Valid — uruchamia kontrolę ograniczeń z DTO odebranego w kontrolerze.
@RestControllerAdvice — wspólna obsługa wyjątków kontrolerów.
@ExceptionHandler — wybiera metodę obsługującą dany typ wyjątku i odpowiedź HTTP.

JPA i baza:
@Entity — klasa mapowana przez JPA. Samo @Entity nie tworzy tabeli; decyduje
konfiguracja schematu/migracji, obecnie ddl-auto=update.
@Table — jawna nazwa tabeli, np. transactions.
@Id — klucz główny encji.
@GeneratedValue — sposób generowania id; IDENTITY deleguje je bazie przy zapisie.
@Column — właściwości kolumny, np. nullable=false i unique=true.
NOT NULL nie zabrania pustego tekstu lub spacji: do tego służy walidacja DTO.
@ManyToOne — wiele transakcji wskazuje jedno konto. LAZY oznacza możliwość
opóźnionego doczytania relacji; nie gwarantuje braku dodatkowych zapytań.
@JoinColumn — kolumna relacji, tutaj account_id wskazujące konto.
@Enumerated — zapis enuma jako STRING zamiast zależnego od kolejności numeru.
@Transactional — granica transakcji bazodanowej. Zapis historii i salda
kończy się razem; domyślnie wyjątek RuntimeException wycofuje zmiany.
Działa przez proxy Springa: zwykłe wywołanie metody na tym samym obiekcie może
ominąć przechwycenie. readOnly w prognozie opisuje odczyt, nie jest zabezpieczeniem
przed każdym możliwym zapisem. Atomowość nie rozwiązuje utraconych aktualizacji
przy równoczesnych zmianach tego samego salda; potrzeba blokady lub wersjonowania.

Walidacja DTO:
@NotNull — wartość musi istnieć; tekst "" lub "   " nadal może przejść.
@NotBlank — tekst nie może być null, pusty ani składać się tylko z białych znaków.
@Positive — liczba >0, np. kwota operacji. Samo nie wymaga nie-null.
@PositiveOrZero — liczba >=0, np. saldo początkowe; łączone z @NotNull.
@Pattern — tekst musi pasować do wyrażenia, tutaj INCOME|EXPENSE.
@Size — ograniczenie długości, np. nazwy konta do 100 znaków.

Java i testy:
@Override — kompilator sprawdza, czy metoda nadpisuje/implementuje istniejącą
metodę; DemoDataLoader.run implementuje CommandLineRunner.
@SpringBootTest — uruchamia kontekst aplikacji w teście; RANDOM_PORT wybiera
wolny port, a właściwości testu kierują na H2, nie na PostgreSQL.
@Value — wstrzykuje wartość konfiguracji, tutaj losowy port serwera testowego.
@Test — metoda będąca przypadkiem testowym JUnit.
@BeforeEach — przygotowanie przed każdym testem.
@Mock — pole będące atrapą zależności Mockito, np. repozytorium.
@InjectMocks — Mockito składa testowany obiekt z mocków; to nie jest DI Springa.
Mock musi być zainicjalizowany (w istniejącym teście robi to openMocks).

Angular/TypeScript — dekoratory, nie adnotacje Javy:
@Component — łączy klasę komponentu, selector, szablon, style i imports.
@Injectable — rejestruje usługę DI. providedIn:'root' udostępnia ją w głównym
injectorze aplikacji. Typ danych Account nie zastępuje klasy AccountService.
@Input — wejście komponentu, np. nazwa ikony oraz dane/stany panelu prognozy.
@HostListener — nasłuch zdarzenia; Escape zamyka dialog, gdy nie trwa zapis.
@if, @else, @for i @empty to bloki sterujące SZABLONU, nie dekoratory klas.
@for z track id identyfikuje wiersze, a @empty wyświetla brak wyników.

Przykładowe zapisy NIEOBECNE obecnie: @Autowired, @Scheduled, @Aspect,
@PreAuthorize, @Version, @Data, @Getter i @Setter. Nie dopisujemy ich do listy
użytych tylko dlatego, że występują w internetowych przykładach. Konstruktory
wstrzykują zależności bez @Autowired, gdy klasa ma jeden konstruktor.
